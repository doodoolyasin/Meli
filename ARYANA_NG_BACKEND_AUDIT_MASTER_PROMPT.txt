DOMAIN 1: TCP MSS Clamping & PMTU Blackhole Elimination
--------------------------------------------------------------------------------
Files:
  - android/app/src/main/java/app/slipnet/tunnel/TcpPacketBuilder.kt (Lines 170-175, 230-235)
  - android/app/src/main/java/app/slipnet/tunnel/TunnelConnection.kt (Lines 34, 336-351)
Defect:
  The TCP Maximum Segment Size (MSS) option is hardcoded to 1460 in both IPv4 and IPv6
  SYN-ACK packets. In DNS tunnels with low MTU (e.g., 1200, 1280, or 512 bytes), client
  browsers negotiate 1460 MSS and emit 1500-byte packets with Don't Fragment (DF=1).
  The Linux kernel TUN driver rejects packets exceeding its configured MTU with EINVAL/EMSGSIZE.
  Because TunnelConnection chunks payloads at a fixed MAX_TCP_PAYLOAD = 1460, oversized
  TLS handshake packets are silently dropped, causing infinite web page loading spinners.
Fix:
  1. Pass the active tunnel MTU (`vpnMtu`) into TcpPacketBuilder and TunnelConnection.
  2. Dynamically compute clamped MSS:
       IPv4: mss = minOf(clientMss ?: (vpnMtu - 40), vpnMtu - 40)
       IPv6: mss = minOf(clientMss ?: (vpnMtu - 60), vpnMtu - 60)
  3. Replace constant MAX_TCP_PAYLOAD with effectiveMss:
       val effectiveMss = maxOf(480, vpnMtu - 40)

DOMAIN 2: One's Complement Checksum Zero Inversion (RFC 793 / 1624 / 8200)
--------------------------------------------------------------------------------
Files:
  - android/app/src/main/java/app/slipnet/tunnel/TcpPacketBuilder.kt (Lines 271-276, 319-324, 369-374)
Defect:
  In calculateIpChecksum, calculateTcpChecksumV4, and calculateTcpChecksumV6, the 16-bit
  folded sum is inverted: `return (sum.inv() and 0xFFFF).toInt()`.
  Per RFC 793 and RFC 8200 Section 8.1, in one's complement arithmetic, an evaluated
  checksum of 0x0000 MUST be transmitted as 0xFFFF. In TCP and IPv6, a raw 0x0000 checksum
  is structurally illegal and treated by upstream carrier middleboxes as packet corruption,
  resulting in silent carrier packet drops.
Fix:
  In all three checksum functions, enforce:
    val checksum = (sum.inv() and 0xFFFF).toInt()
    return if (checksum == 0) 0xFFFF else checksum

DOMAIN 3: Raw IP Packet Fragment Offset Guard (Mid-Fragment TCP Corruption)
--------------------------------------------------------------------------------
Files:
  - android/app/src/main/java/app/slipnet/tunnel/IpPacketParser.kt (Lines 118-130)
Defect:
  In `parseIpv4`, when protocol == IPPROTO_TCP, `parseTcpHeader(data, ihl)` is executed
  without checking the Fragment Offset field. In fragmented IP datagrams, bytes following
  the IHL in non-first fragments (fragOffset > 0) contain raw fragmented payload, NOT a
  TCP header. Parsing payload as a TCP header interprets random payload bytes as TCP flags;
  if bit 2 (SYN) or bit 4 (RST) is set, active sessions are immediately reset or corrupted.
Fix:
  Extract flags and fragment offset from IPv4 header bytes 6-7:
    val flagsAndFrag = ((data[6].toInt() and 0xFF) shl 8) or (data[7].toInt() and 0xFF)
    val fragOffset = (flagsAndFrag and 0x1FFF) * 8
    val tcpHeader = if (protocol == Protocol.TCP && fragOffset == 0 && data.size >= ihl + 20) {
        parseTcpHeader(data, ihl)
    } else null

DOMAIN 6: Rust FFI Exception Safety & Panic Unwinding Boundary (SIGABRT Prevention)
--------------------------------------------------------------------------------
Files:
  - android/app/src/main/rust/slipstream-rust/crates/slipstream-client/src/meli.rs (Lines 722-836)
  - android/app/src/main/rust/slipstream-rust/crates/slipstream-client/src/android.rs (Lines 204, 625-665)
  - android/app/src/main/rust/slipstream-rust/crates/slipstream-client/src/streams.rs (Lines 686-791)
Defect:
  Rust `extern "C"` / `extern "system"` entrypoints lack `std::panic::catch_unwind`. In Rust
  2021 edition and LLVM 17+, any unwinding panic traversing an FFI boundary immediately triggers
  `std::process::abort()`, terminating Android with signal SIGABRT.
  Specifically, in `meli.rs:835`:
    `env.new_string(err).unwrap_or_else(|_| env.new_string("").unwrap())`
  Calling `.unwrap()` on JNI calls panics upon Out-Of-Memory or pending exceptions.
Fix:
  Enclose all FFI function bodies in `std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| { ... }))`.
  Return null pointers or defined negative error codes on failure. Remove all `.unwrap()` calls.

DOMAIN 9: Orphaned Daemon Process Reaping & Port Lock Reclamation (PR_SET_PDEATHSIG)
--------------------------------------------------------------------------------
Files:
  - android/awgcore/main.go (Line 1 et seq.)
  - android/app/src/main/java/app/slipnet/SlipNetApp.kt
  - android/app/src/main/java/app/slipnet/tunnel/SingBoxBridge.kt
  - android/app/src/main/java/app/slipnet/tunnel/NativeCore.kt
Defect:
  When the JVM is terminated via SIGKILL (Android Low Memory Killer or task swipe), child
  executables launched via ProcessBuilder (`libsingbox.so`, `libawg.so`, `libnaive.so`)
  are re-parented to PID 1 (`/init`). They continue running and hold local ports (10808, 10880)
  bound. When the app restarts, `net.Listen` fails with `bind: address already in use` (EADDRINUSE).
Fix:
  1. In Go child daemons, register parent death signal in `init()`:

           for {
               if _, err := os.Stdin.Read(b); err != nil {
                   os.Exit(0)
               }
           }
       }()
  2. In `SlipNetApp.onCreate()`, scan `/proc` for processes matching daemon names under
     the app's Linux UID and send SIGKILL before starting services.

DOMAIN 10: Stream Cipher Nonce Directionality & Two-Time Pad Prevention (AES-CTR)
--------------------------------------------------------------------------------
Files:
  - pkg/tunnel/tunnel.go (Lines 122-123, 436-437)
  - pkg/tunnel/proto/proto.go (Lines 103-112)
Defect:
  In `pkg/tunnel`, client request chunks and server response chunks derive an identical
  AES-CTR IV using `DeriveIV(sessionID, seq, 0)`.
  In AES-CTR stream cipher mode, identical IVs with an identical key produce identical
  keystreams ($C_{req} \oplus C_{resp} = P_{req} \oplus P_{resp}$), completely stripping
  encryption and leaking plaintexts to any passive eavesdropper.
Fix:
  Introduce a directional salt in `DeriveIV`:
    func DeriveIV(sessionID uint8, seq uint16, frag uint8, isDownlink bool) []byte {
        iv := make([]byte, 16)
        if isDownlink {
            iv[0] = 0xD0 // Downlink domain separation
        } else {
            iv[0] = 0x0D // Uplink domain separation
        }
        iv[1] = sessionID
        binary.BigEndian.PutUint16(iv[2:4], seq)
        iv[4] = frag
        ...
    }

DOMAIN 11: Random Nonce Collision Resilience (XChaCha20-Poly1305 vs ChaCha20)
--------------------------------------------------------------------------------
Files:
  - internal/security/codec.go (Lines 258-284)
Defect:
  ChaCha20-Poly1305 and AES-GCM use 96-bit random nonces generated via `rand.Read(nonce)`.
  Per NIST SP 800-38D and birthday paradox bounds, generating random 96-bit nonces under
  a static shared key reaches high collision probability after $2^{32}$ packets.
  A single nonce reuse in Poly1305/GHASH exposes the internal authentication key,
  allowing arbitrary message forgery.
Fix:
  Switch high-throughput tunnels to **XChaCha20-Poly1305** with 192-bit (24-byte) nonces
  via `golang.org/x/crypto/chacha20poly1305.NewX(key)`, where random nonce collisions
  are mathematically impossible ($2^{-96}$ bound).

DOMAIN 12: Constant-Time Cryptographic Verification (Timing Attack Elimination)
--------------------------------------------------------------------------------
Files:
  - internal/client/session.go (Lines 145-155)
  - internal/security/fingerprint.go
Defect:
  Session handshake verification codes and authentication tokens are verified using
  `bytes.Equal(sessionAccept.VerifyCode[:], verifyCode[:])`.
  `bytes.Equal` short-circuits on the first byte mismatch, creating a side-channel timing
  leak that enables network adversaries to brute-force session verify codes byte-by-byte.
Fix:
  Replace all token and MAC comparisons with `crypto/subtle`:
    if subtle.ConstantTimeCompare(sessionAccept.VerifyCode[:], verifyCode[:]) != 1 {
        return ErrSessionInitFailed
    }

DOMAIN 15: Base36 Non-Canonical Bit-Overflow Aliasing & Zero Remainder Verification
--------------------------------------------------------------------------------
Files:
  - internal/basecodec/lowerbase36.go (Lines 108-117, 152-161)
Defect:
  11 Base36 characters represent values up to $36^{11}-1 \approx 1.31 \times 10^{17}$, whereas
  7 bytes of data hold a maximum of $2^{56}-1 \approx 7.20 \times 10^{16}$.
  When decoding, the accumulator `val` is shifted right by 8 for each byte, but the residual
  bits in `val` are never checked. Non-canonical strings (e.g. "zz" vs "0f") decode to identical
  plaintexts, enabling signature malleability and cache poisoning.
Fix:
  After extracting all block bytes, assert that no residual bits remain:
    if val != 0 {
        return nil, ErrInvalidLowerBase36
    }

DOMAIN 16: Decompression Bomb (OOM) Protection in LZ4 / ZSTD Block Engines
--------------------------------------------------------------------------------
Files:
  - internal/compression/types.go (Lines 24, 289-301)
Defect:
  In `decompressLZ4`, an uncompressed size header up to 10 MB (`origSize <= maxDecompressedSize`)
  triggers an immediate heap allocation: `out := make([]byte, origSize)` before validating
  compressed data integrity. An 8-byte UDP packet can force 10 MB RAM allocations, crashing
  mobile devices via Out-Of-Memory (LMK).
Fix:
  1. Reduce max single-packet decompressed size from 10 MB to 128 KB (`maxDecompressedSize = 128 * 1024`).
  2. Enforce the maximum LZ4 expansion ratio (255:1):
       if origSize > uint32(len(data)-4) * 256 {
           return nil, ErrInvalidLZ4Ratio
       }
  3. Validate buffer capacities before returning to `deflateBufferPool` to prevent pool bloating.

DOMAIN 17: AmneziaWG Camouflage Parameter Unsigned Underflow Panic Guard
--------------------------------------------------------------------------------
Files:
  - work/awg/device/noise-protocol.go (Line 639)
  - work/awg/device/uapi.go (Lines 355-381)
Defect:
  In `JunkPackets()`, packet length is computed as `make([]byte, min + fastrandn(max - min))`.
  Because `min` and `max` are `uint32`, if $J_{min} > J_{max}$ or if $J_{max}$ is uninitialized,
  `max - min` underflows to $\sim 4.29 \times 10^9$. Calling `make([]byte, ...)` panics with
  `makeslice: len out of range` or crashes the process via OOM.
Fix:
  Validate parameters in UAPI and clamp in noise-protocol:
    if max < min {
        min, max = max, min
    }
    buf := make([]byte, min + fastrandn(max - min + 1))

DOMAIN 18: AmneziaWG Anti-Replay Sliding Window Ring Buffer Reset Cleanliness
--------------------------------------------------------------------------------
Files:
  - work/awg/replay/replay.go (Lines 30-33)
Defect:
  `replay.Filter.Reset()` only clears index 0 of its 128-block ring:
    `f.last = 0; f.ring[0] = 0`
  Blocks 1..127 retain bitmasks from previous sessions. Upon session rekeying, legitimate
  sequential packets arriving in subsequent blocks match stale bits and are discarded as replays.
Fix:
  Fully clear the entire ring buffer:
    func (f *Filter) Reset() {
        f.last = 0
        clear(f.ring[:])
    }

DOMAIN 19: SMUX v2 Keepalive Ping/Pong Watchdog Deadlock Elimination
--------------------------------------------------------------------------------
Files:
  - internal/streamutil/ (and external xtaci/smux integration)
Defect:
  In SMUX v2, `writeFrameInternal` queues ping frames into `shaper` and blocks on `<-resultCh`
  without a deadline. If the underlying network transport stalls, the single keepalive goroutine
  hangs forever. The timeout channel (`<-tickerTimeout.C`) is never read, disabling the session
  inactivity watchdog and leaving frozen dead sessions hanging forever.
Fix:
  Ensure `writeFrameInternal` enforces a strict deadline on the second select:
    select {
    case result := <-resultCh:
        return result.n, result.err
    case <-deadline:
        return 0, ErrTimeout
    case <-s.die:
        return 0, io.ErrClosedPipe
    }

DOMAIN 20: 64-bit Memory Alignment for ARM 32-bit Architecture (SIGBUS Prevention)
--------------------------------------------------------------------------------
Files:

  unpadded 8-bit and 32-bit fields. On 32-bit ARM (ARMv7 / armeabi-v7a), struct offsets

DOMAIN 21: Multi-Level Queue (MLQ) Priority Inversion & Heartbeat Starvation Prevention
--------------------------------------------------------------------------------
Files:
  - internal/enums/packet_priority.go (Lines 75-78)
  - internal/client/dispatcher.go (Lines 172-196)
Defect:
  PACKET_PING and PACKET_PONG are assigned `PacketPriorityIdle` (Priority 5). In `dispatcher.go`,
  stream 0 is skipped if any other stream has pending data (`if hasOtherWork { continue }`).

DOMAIN 22: LeakyBucket Pacer Monotonic Clock Drift & Backward Time Jump Lockup Guard
--------------------------------------------------------------------------------
Files:
  - pkg/pacer/pacer.go (Lines 31-37, 64-69)
Defect:
  In `Allow(n)`, `elapsed := now.Sub(b.last).Seconds()` is added directly: `b.tokens += elapsed * b.rate`.
  If system time jumps backward (via NTP or cellular time sync), `elapsed` is negative,
  plunging `tokens` into large negative values and blocking all packet transmission for seconds or minutes.
Fix:
  Use monotonic time calculations and clamp negative elapsed values:
    if elapsed < 0 {
        b.last = now
        elapsed = 0
    }
    b.tokens = min(b.capacity, b.tokens + elapsed * b.rate)
    b.last = now

  floods Android's IPC binder and triggers an application ANR (Application Not Responding).
Fix:
  Shift observation to background dispatchers and throttle updates:
    ScanStateHolder.state
        .sample(500L) // Limit to at most 2 updates per second
        .flowOn(Dispatchers.Default)
        .collect { s -> ... }

DOMAIN 29: DNS Negative Cache (NXDOMAIN) Storm & Sliding Window Eviction Quota

Files:

DOMAIN 30: TrafficStats 4.3 GB/s Integer Spike Elimination & Monotonic Speed Calculation
--------------------------------------------------------------------------------
Files:
